# Chapter 7: Repair Validator & Repair Applier

This chapter details the two core components enforcing the thesis **"AI Proposes, Compiler Validates"**: the non-mutating deterministic gatekeeper (**`RepairValidator`**) and the atomic mutation executor (**`RepairApplier`**).

---

## 1. The Repair Validator: 6 Non-Mutating Invariant Checks

The `RepairValidator` ([`compiler/include/neuroparse/recovery/repair_validator.hpp`](file:///c:/Users/shiva/OneDrive/Desktop/neurology/compiler/include/neuroparse/recovery/repair_validator.hpp)) acts as the strict verification gate. Every candidate `RepairPrediction` generated by a neural model must pass all 6 checks before any modification to the token stream is allowed.

```
                  ┌───────────────────────────────┐
                  │ Candidate RepairPrediction    │
                  └───────────────┬───────────────┘
                                  ▼
      ┌────────────────────────────────────────────────────────┐
      │                   RepairValidator                      │
      │                                                        │
      │  [Check 1] operation_validity                          │
      │  [Check 2] position_bounds                             │
      │  [Check 3] token_validity                              │
      │  [Check 4] parser_context_compatibility (expectation)  │
      │  [Check 5] structural_safety (EOF protection)          │
      │  [Check 6] forward_progress (prevents repetition)      │
      └───────────────────────────┬────────────────────────────┘
                                  │
                   ┌──────────────┴──────────────┐
                   ▼                             ▼
              All Passed                     Any Failed
             [ ACCEPTED ]                   [ REJECTED ]
                   │                             │
                   ▼                             ▼
            RepairApplier                Classical Fallback
```

### The 6 Verification Stages:

| # | Check Name | Rule & Rejection Criteria |
|---|---|---|
| **1** | `operation_validity` | Verifies `operation` is one of `InsertToken`, `DeleteToken`, `ReplaceToken`, `NoRepair`. Rejects `Unknown` or unhandled operations. |
| **2** | `position_bounds` | Ensures `position_offset` maps to a valid index in the token stream without exceeding sequence bounds. |
| **3** | `token_validity` | Validates that proposed inserted/replaced token types exist in the NeuroLang vocabulary and have legal lexemes. |
| **4** | `parser_context_compatibility` | If parser expectations (`expected_tokens`) are recorded, verifies that the proposed token matches at least one expectation. |
| **5** | `structural_safety` | Prohibits deleting or replacing the terminating `TokenType::Eof` token. Prohibits illegal bracket inversions. |
| **6** | `forward_progress` | Guarantees that applying the repair will advance parsing rather than recreating the exact same error state. |

## 3. The Repair Applier (`RepairApplier`)

The `RepairApplier` ([`compiler/include/neuroparse/recovery/repair_applier.hpp`](file:///c:/Users/shiva/OneDrive/Desktop/neurology/compiler/include/neuroparse/recovery/repair_applier.hpp)) executes atomic mutations on `std::vector<Token>& tokens`.

```cpp
RepairApplyResult RepairApplier::apply(
    std::vector<lexer::Token>& tokens,
    std::size_t& cursor,
    const RepairPrediction& prediction) const;
```

### Atomic Operations & Cursor Realignment:

1. **`apply_insert`:**
   - Synthesizes a new `Token` with correct type, lexeme, and interpolated `SourceLocation`.
   - Inserts the token at `tokens.begin() + target_pos`.
   - Adjusts parser cursor: sets `cursor = target_pos` so the parser immediately evaluates the inserted token.

2. **`apply_delete`:**
   - Erases the token at `tokens.begin() + target_pos`.
   - Adjusts parser cursor: keeps `cursor = target_pos` (which now points to the subsequent token).

3. **`apply_replace`:**
   - Mutates `tokens[target_pos].type` and `tokens[target_pos].lexeme` in place.
   - Adjusts parser cursor: sets `cursor = target_pos` to re-parse the corrected token.

4. **`apply_no_repair`:**
   - Leaves tokens and cursor unchanged; returns `RepairApplyStatus::NoRepair`.

### Invariants Maintained by `RepairApplier`:
- **EOF Preservation:** Under no circumstance is the final EOF token erased.
- **Bound Safety:** All mutations execute inside vector limits `[0, tokens.size()]`.
